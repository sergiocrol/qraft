# Implementation Plans

Generated by the `improve` skill on 2026-07-03, against the initial audit of Qraft.ai.

These plans came out of a full-repo audit of Qraft.ai (artistic-QR generator: Astro/React
client, Express-on-Lambda API, Python/Flask SageMaker inference container, shared `@repo/*`
packages). The dominant theme: **the API was written for a long-lived Express server but runs
on Lambda**, where any work done after the HTTP response is frozen — that's the root of the
most severe bug (002) and several deferred ones. The second theme: **no verification baseline**
(001) gates everything else. The third: **unauthenticated surfaces** (003) and a **validation
contract reimplemented three times** (006).

Each executor: read the plan fully before starting, honor its STOP conditions, run the drift
check first, and update your row below when done. Plans are self-contained — you do not need
this audit or any other plan to execute one, except where "Depends on" says so.

## Dependency notes

- **001 before 002, 003, 006**: those change security/correctness-critical logic; the
  characterization tests from 001 are their safety net. 005 needs 001 only for the TypeScript
  schema test; its Python changes are gated by `py_compile`.
- **003 ↔ 004**: both are API security; 003 admin-gates `/api/jobs` using the `adminAuth`
  middleware whose JWT bug 004 fixes. Land 004 first if doing both, but they're independent.
- **003 → direction D2**: the per-job access token 003 introduces is the mechanism a future
  "shareable/ownable result links" feature (D2) would build on.
- **005 ↔ 006**: both edit `apps/controlnet/app/schemas/generate.py` / the Zod schema. If
  landing both, reconcile the diffs (005 touches `baseQrCode`, 006 touches numeric bounds).
- **007 coordinate with 004**: both may edit `apps/api/src/routes/endpoint.ts`.
- **008 ↔ 005/006**: 008 (generation quality v2) adds optional fields to the same
  schema files 005/006 edit and reorganizes `inference.py` (005's line anchors move).
  Land 005/006 first when possible; 008 only *adds* optional fields and must never
  change existing bounds. 008 was planned 2026-07-04 from web research (DiffQRCoder
  WACV'25, monster-v2 model card, antfu's QR-101, Dynamsoft decoder benchmark) —
  sources cited inside the plan.
